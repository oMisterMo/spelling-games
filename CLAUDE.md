# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A collection of spelling games for kids ages 4–12, rendered with PixiJS v8 (TypeScript, bundled with Vite). There are nine game slots so far: Crossword, Word Search, ABC Order, Word Scramble, Missing Letters, Spelling Bee, Speedy Speller, Balloon Pop and Hungry Monster. All nine games are playable. `src/games/PlaceholderGame.ts` is kept for stubbing out new games in the registry.

## Commands

- `npm run dev`: start the Vite dev server
- `npm run build`: type-check with `tsc`, then build to `dist/`
- `npx tsc`: type-check only (`noEmit`; `strict`, `noUnusedLocals` and `noUnusedParameters` are on)
- `npm run preview`: serve the production build

There is no test runner or linter configured.

## Architecture

The app is one full-window Pixi `Application` (`resizeTo: window`), created in `src/main.ts`. Only one screen is shown at a time.

- **Scenes** (`src/core/Scene.ts`): every screen, whether the menu or a game, extends the abstract `Scene`, which is a Pixi `Container`. The lifecycle hooks are `onEnter()`, `onExit()`, `update(ticker)` (called every frame) and `resize(width, height)`, which is required. Build display objects in the constructor, and do **all** positioning in `resize()`. It runs right after the scene is shown and again whenever the window size changes.
- **SceneManager** (`src/core/SceneManager.ts`): `goTo(scene)` calls `onExit()` on the old scene and then destroys it along with its children, so a scene can't be reused after you leave it. Always create a new instance. The manager forwards the ticker and renderer `resize` events to the current scene. Scenes get the manager through their constructor so they can navigate.
- **Game registry** (`src/games/registry.ts`): the `GAMES` array is the only place games are listed. `MenuScene` creates one button per entry (switching a phone-width menu to two columns when one column would not fit), and each entry's `create(scenes, info)` factory makes the game's scene. To add a real game, create a `Scene` subclass (e.g. `src/games/crossword/CrosswordGame.ts`) and point its registry entry's `create` at it instead of `PlaceholderGame`. Give an entry a `textColor` when its `color` is too light for white text.
- **Circular import**: `MenuScene` → `registry` → game scenes → `MenuScene`, because games create a new `MenuScene` to go back. This works only because `create` is a lazy arrow function. Don't instantiate scenes when a module first loads.
- **UI** (`src/ui/`): `Button` is a rounded button whose origin is its center. Call `setSize()` to resize it again from inside a scene's `resize()`. Its label shrinks to fit instead of wrapping, so use `\n` for multi-line labels. `WinOverlay` is the end-of-game card: call `layout()` from `resize()` and `show(tweens)` on a win. `Tile` is the shared tile; ABC Order, Word Scramble and Missing Letters subclass it to add their own state. `ClueCard` is the white picture-and-clue card used by Word Scramble, Missing Letters, Spelling Bee, Balloon Pop and Hungry Monster: call `setClue()`, then `layout()`. `LetterKeyboard` is the on-screen keyboard used by Crossword, Spelling Bee and Balloon Pop. It shows the full A–Z or a single letter-bank row, both ending with `BACKSPACE` unless the constructor's `backspace` argument is false: call `setLetters()`, then `measure()` and `layout()`. `WinOverlay.setMessage()` changes the end message; Spelling Bee uses it to show a score. `theme.ts` holds the shared fonts (including `EMOJI_FONT_FAMILY` for clue pictures) and dark color.
- **Shared game building blocks**: each playable game has `levels.ts` (level config) and `levelSelect.ts`. The latter is a function that builds the generic `src/scenes/LevelSelectScene`; the game scene imports it for its "← Levels" button. `src/core/Tweens.ts` is the animation runner: a scene owns a `Tweens` instance and calls `tweens.update(ticker.deltaMS)` from `update()`. Keep puzzle/word-picking logic in Pixi-free modules that take an injectable `random` (`src/core/random.ts` has `shuffle`).
- **Name clashes with Pixi**: a `Container` subclass (every `Scene` is one) must not declare `label`, `cursor` or `setSize` with a different type, because `Container` already defines them. `Button.setSize(width, height)` is compatible; the shared `Tile` uses `resizeTile`, and the crossword uses `caret` for its typing position.
- **Word lists** (`src/data/wordLists.ts`): `WORD_LISTS` holds the words for every game, grouped by level (`easy` / `medium` / `hard`, for ages 4–6, 7–9 and 10–12). The user edits this file directly. Each entry is a plain string or a `WordInfo` (`{ word, clue?, picture? }`, where `picture` is usually an emoji). Games should read words through `getWords(level)` (strings) or `getWordInfos(level)` (with clues). Both uppercase the words, remove non-letters and drop duplicates. They shouldn't read `WORD_LISTS` directly. Crossword filters to entries that have a `clue`.
- **Hungry Monster** (`src/games/hungry-monster/`): pick the right spelling out of a few look-alikes. `misspell.ts` (Pixi-free) makes the wrong spellings: likely mistakes first (the `SOUND_ALIKES` swaps, doubled or undoubled letters, two neighbouring letters swapped, always keeping the first letter), then changed vowels as a fallback. It never returns a word in the `avoid` set, which the game fills with every word from all three lists, and `makeChoices` returns null for a word with too few misspellings so the round is skipped. In `HungryMonsterGame` each `ChoiceCard` has a `state` (`open` / `wrong` / `eaten`): a wrong card is crossed off and stays in its `homes` spot, the right one flies to `Monster.mouthPoint`. There is no way to lose; `firstTryCount` feeds the end message. `Monster` is drawn in "units" chosen in `layout()` and needs `update(deltaMS)` every frame. The cards go in one row, one column or two columns depending on the space. Speech stops in `onExit`.
- **Balloon Pop** (`src/games/balloon-pop/`): a letter-guessing game (a gentle hangman). `BalloonPopGame` keeps the `guessed` letters; a right guess shows the letter in every cell it belongs to, and a wrong one calls `BalloonBunch.pop()`. Used keys are turned off in place (`markKey`: green tint or faded), found through `keyboard.keys` by A–Z index, and the keyboard is rebuilt each round. When `bunch.remaining` hits 0 the word is shown in orange and the game moves on; `solvedCount` feeds the end message. `BalloonBunch` draws the rider, balloons and hill in "units" chosen in `layout()`, and needs `update(deltaMS)` every frame for its bobbing. Sounds are in `sounds.ts`. Speech stops in `onExit`.
- **Spelling Bee** (`src/games/spelling-bee/`): `src/core/speech.ts` wraps the browser's Web Speech API (`speak`, `stopSpeaking`, `canSpeak`). Words are spoken lowercase, because an all-caps word can be read out as separate letters. When `canSpeak` is false, the picture and clue are always shown and words without a clue are dropped. `SpellingBeeGame` keeps `letters`, `locked` and `given` per box, plus a `caret`. A filled word is checked right away: right letters lock, wrong ones clear after a red flash, and after `maxTries` wrong attempts the answer is revealed. `firstTryCount` feeds the end message. Speech stops in `onExit`.
- **Speedy Speller** (`src/games/speedy-speller/`): a timed game. Each round shows the word on an intro screen, then a grid holding `copies` sets of its letters (`makeGrid.ts`, Pixi-free); the word must be spelled `copies` times by tapping tiles in order before `seconds` run out. `SpeedySpellerGame` has a `phase` (`intro` / `playing` / `done`); the clock only runs while `playing`, driven from `update()`. `attempt` holds the tiles picked for the current copy, and `busy` blocks input briefly while a finished copy is cleared. `startRound` replaces the `Tweens` instance to drop animations on destroyed tiles. Each level has a theme from `themes.ts` (turtles, clouds or meteors) that sets the `SpellerTile` drawing, the animated `Backdrop` and how tiles are dismissed. `ResultCard` is this game's own end card with a star rating, used after every word and for the final summary. Sounds are Web Audio beeps from `src/core/sfx.ts` (`tone`). Speech stops in `onExit`.
- **Missing Letters** (`src/games/missing-letters/`): `makePuzzle.ts` hides letters (never the first letter when `keepFirstLetter` is set, and always leaving another letter showing). It then adds distractors from the same vowel/consonant class as the answers. `MissingLettersGame` runs rounds like Word Scramble. Each `WordCell` is a given letter or a blank, and `selected` is the blank the next letter goes into. `ChoiceTile`s keep their row spot once used. A choice is checked the moment it's tapped or typed: a right one flies into the blank, a wrong one shakes. `busy` blocks input only while moving to the next word.
- **Word Scramble** (`src/games/word-scramble/`): `scramble.ts` picks the rounds (skipping words that are too long or have only one distinct letter) and shuffles each word so it never comes out in its original order. `WordScrambleGame` runs several rounds in one scene: `startRound` destroys and rebuilds the `LetterTile`s, then calls `resize()` again. Each tile is either in an answer slot or its reserved pool spot (`slot: number | null`, `poolIndex`). Correctness is checked by letter, so repeated letters are interchangeable. When the slots are full, correct letters lock and wrong ones return to the pool. Hint locks the next correct letter. The game listens for physical keys on `window` (`onEnter`/`onExit`).
- **Crossword** (`src/games/crossword/`): `generateCrossword.ts` runs several random attempts and keeps the one with the most words, then the smallest area. Each attempt places words so they cross an existing word and never touch another word side by side or end to end, which means every run of letters is exactly one entry. It then crops the grid and numbers the start cells in reading order. In `CrosswordGame`, state is kept per cell (`letters`, `locked`), plus `cellEntries` (the entry indexes through each cell) and `caret`. A word is evaluated once all its cells are filled: correct words lock (which can complete crossing words, so `solve` recurses), and wrong letters are cleared after a red flash. The game listens for physical keys on `window`, adding the listener in `onEnter` and removing it in `onExit`. In letter-bank mode (Easy), `selectEntry` rebuilds the on-screen keyboard and calls `resize()` again.
- **ABC Order** (`src/games/abc-order/`): `pickWords.ts` chooses the words. Easy and Medium use distinct first letters. Hard (`sharedFirstLetter`) forces at least one pair sharing a first letter, and the order shown is never already sorted. In `AbcOrderGame`, `WordTile`s sit either in a numbered slot or in their reserved tray spot (`slot: number | null`). A press that moves less than `DRAG_THRESHOLD` counts as a tap. When all slots are full, the game checks the order: correct tiles lock, and wrong ones return to the tray.
- **Word Search** (`src/games/word-search/`): the level select starts `WordSearchGame` with a `WordSearchLevel` from `levels.ts`. That config sets the grid size, word count, allowed directions and which word list to use. `generatePuzzle.ts` is pure logic with no Pixi and takes an injectable `random`. The scene matches a selection by its letters, forwards or backwards, rather than by the placement's position. It supports both dragging and tapping the first letter then the last, and runs its animations through a small tween list driven by `update()`.

## Debugging

In dev builds, `main.ts` sets `globalThis.__PIXI_APP__` for the PixiJS DevTools extension. Browser automation can use it too: `__PIXI_APP__.stage.children[0]` is the current scene. Its fields are TypeScript-private but readable at runtime, e.g. `puzzle.placements` on a word search. Headless browsers usually have no voices, so to test Spelling Bee, replace `speechSynthesis.speak` in an init script (e.g. Playwright's `addInitScript`) with a function that records `utterance.text` and `utterance.rate`.

## Conventions

- Uses the PixiJS v8 API: `await app.init({...})`, `new Text({ text, style })`, and chained `Graphics` calls (`.roundRect(...).fill(...)`), plus `eventMode = 'static'` and `pointertap` for input. Don't use v7-style constructors.
- The audience is young children, so use large touch targets and fonts. Layouts must work from phone width (about 400px) up to desktop.
